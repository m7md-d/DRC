# ترسانة DRC وحدود الدعم

**التاريخ:** 13 أكتوبر 2026. القائمة خطة دمج، وليست إعلانًا أن كل أداة مثبتة أو مختبرة حاليًا.

## 1. قاعدة اختيار الأدوات

نعتمد أدوات متخصصة ونبني حولها هوية الجهاز، وسياسة السلامة، وإدارة الجلسة، وعرض المخرجات كاملة بقيمها وأسمائها الأصلية إلى جانب تسميات الواجهة. القدرة مرتبطة بالأداة وإصدارها ونظام المضيف ومسار التوصيل ونظام ملفات القرص، وهذه محاور مستقلة.

لا يولد DRC تشخيصًا أو احتمالات سبب عطل أو توصية إجراء. المعلومات التي يعلنها جهاز أو أداة تعرض منسوبة إلى المصدر، وتبقى جميع حقولها وأعلامها ومخرجاتها الأصلية متاحة في العرض المنظم والسجل؛ لا حقول مفقودة بسبب parser ولا درجة صحة بديلة عنها.

أقراص ويندوز ضمن النطاق الأساسي عند تشغيل التطبيق على الماك. الأولوية NTFS/exFAT/FAT، مع قارئات قابلة للتبديل، وطبقات مستقلة للتشفير والحاويات. النسخ الخام لا يتوقف على معرفة نظام الملفات أو قدرة النظام على تركيبه.

قراءة بيانات متاحة لا تعني بدء اختبار داخلي أو مسح كامل. كل adapter يصف أثر العملية، وليس اسم الأداة فقط؛ smartctl وTestDisk وdiskutil قد تنفذ عمليات قراءة أو كتابة مختلفة.

## 2. أدوات macOS الأساسية

| الأداة/الواجهة | الاستخدام في DRC | حدود أساسية | المرحلة |
| --- | --- | --- | --- |
| Disk Arbitration | ظهور/اختفاء الأجهزة، تغير التركيب، المشاركة في منع تركيب مصادر الحماية | ليس حاجب كتابة لكل البرامج؛ يجب أن تكون الخدمة حاضرة قبل التركيب المطلوب منعه | 1 |
| IOKit / IORegistry | ربط الوسيط بمسار USB/Thunderbolt وبيانات الجهاز | معلومات الجسر لا تساوي دائمًا معلومات SSD خلفه؛ الحقول تختلف | 1 |
| diskutil مع Plist | أقراص وأقسام وحاويات APFS وسعة وحالة تركيب | تُستخدم أفعال محددة؛ لا نسمح للواجهة بتمرير فعل اعتباطي | 1 |
| system_profiler بصيغة JSON | تفاصيل الاتصال من USB وThunderbolt وNVMe عند توفرها | تقارير مكلفة نسبيًا؛ جمع عند الطلب أو التخزين المؤقت، لا استدعاء متكرر | 1 |
| smartctl بصيغة JSON ومخرجات أصلية | معلومات SMART/NVMe والصحة والسجلات المتاحة | دعم USB على Darwin محدود، وقد يحتاج مسارًا/دعمًا خاصًا؛ لا نجرب flags للجسور عشوائيًا | 1 |
| GNU ddrescue + ddrescuelog | صورة خام أو نطاقات، خريطة استكمال، إحصاءات المناطق | يفترض مصدرًا يقدم قطاعات؛ مهل kernel أو فصل الجهاز قد يوقفه؛ التعامل الصحيح مع mapfile ضروري | 2 |
| hdiutil | ربط صورة للقراءة فقط أو دون تركيب ثم تحليلها | تثبيت options بحيث لا تتحول الصورة المرجعية إلى وجهة كتابة | 3 |
| نسخ ملفات بمكتبات النظام / ditto / rsync بإعدادات مختبرة | استخراج ملفات موجودة، وتقدم وحفظ metadata بحسب الوجهة | المصدر مركب قراءة فقط، لا flags حذف/تزامن خطرة، ولا ضغط قراءة غير ضروري على SSD يفصل | 3 |
| Sleuth Kit: mmls، fsstat، fls، icat وغيرها | تحليل الأقسام وmetadata واستخراج الملفات؛ NTFS/exFAT/FAT ضمن أول حزمة على الماك، وقارئات الأنظمة الأخرى مستقلة | دعم كل ميزة وتشفير يحتاج اختبارات؛ مخرجات الأداة كاملة، ولا دعم يستنتج من نظام المضيف | 3 |
| TestDisk | اكتشاف أقسام مفقودة وقراءة بنية واسترجاع ملفات للأنظمة التي يدعمها | له وظائف كتابة؛ analyze ليس تصريحًا بإعادة بناء جدول المصدر | 3 |
| PhotoRec | carving لملفات معروفة التواقيع من صورة | لا يعيد الأسماء والمجلدات الأصلية؛ التشفير والتجزئة والقطاعات الناقصة تحد النتائج | 3 |
| fsck_apfs / fsck_hfs / أدوات FAT وexFAT المناسبة | التحقق دون إصلاح، وإصلاح نسخة عمل لاحقًا | لا تشغيل افتراضي على SSD المريض؛ adapter لكل نظام ملفات، مع إعدادات منع الإصلاح التي توثقها نسخة النظام | 3–4 |
| gpt / diskutil partitioning | قراءة GPT، ثم كتابة أقسام أو تهيئة لاحقًا | تحديد موقع flags مهم؛ gpt لديه -r عالمي للقراءة، و-r خاص بفعل destroy له معنى مختلف | 1 / 4 |

صيغ Plist/JSON، وmount readOnly، وhdiutil -readonly، وfsck -n، ومعنى gpt -r تم التحقق منها في صفحات man المحلية على macOS 15.7.9. ليست جميع أفعال هذه الأدوات مسموحة في وضع حماية المصدر.

[وثيقة Apple](https://developer.apple.com/library/archive/documentation/DriversKernelHardware/Conceptual/DiskArbitrationProgGuide/ArbitrationBasics/ArbitrationBasics.html) تحدد callbacks الموافقة على التركيب وإشعارات الاختفاء. [وثيقة smartctl](https://github.com/smartmontools/smartmontools/blob/main/src/smartctl.8.in) تميز دعم Darwin عن دعم الأنظمة الأخرى؛ الموجود محليًا 7.5 لا يقدم Darwin SCSI عامًا. الجسور المعروفة على Linux ليست وعدًا بتمريرها على Mac.

## 3. أدوات إضافية مفيدة

| الإضافة | فائدتها | قرار الدمج |
| --- | --- | --- |
| عارض Hex ومحلل GPT/MBR داخل DRC | عرض قطاع ونطاق وتواقيع وفحص CRC والنسخة الاحتياطية | قراءة فقط أولًا؛ التحرير الخام مرحلة 4 مع preview وحفظ النسخة السابقة خارج المصدر |
| خريطة نطاقات مبنية على ddrescue | مناطق منقذة/مؤجلة/غير مقروءة وقراءات بطيئة | أساسية في التصوير؛ لا تحتاج فحصًا ثانيًا للمصدر |
| SHA-256 للصور والملفات الناتجة | تثبيت حالة ملف الناتج ومقارنة نسخه | من الوجهة/الصورة؛ لا ادعاء أنها تثبت أن كل قطاعات المصدر استعيدت |
| libewf / صيغة E01 | تبادل صور مع أدوات التحليل الجنائي | مرحلة لاحقة بعد تقييم الإصدار والتراخيص والتوافق؛ الخام هو البداية |
| libfsapfs | قراءة APFS كخيار إضافي خارج التركيب الأصلي | تجريبي ومعزول على الصور؛ لا يجعل المنتج يعتمد عليه وحده |
| fio | أداء وتسلسل/عشوائية وزمن استجابة بإعدادات محدودة | أداة لاحقة للأقراص السليمة أو بعد حفظ البيانات؛ --readonly وقالب مدقق لا يكفيان لتبرير ضغط قرص مريض |
| OpenSuperClone | خيار إنقاذ متقدم في بيئة Linux مناسبة | تكامل لاحق/تبادل ملفات وفق التوافق؛ ليس backend أصليًا للماك ولا حلًا متخصصًا سحريًا لكل NVMe |
| R-Studio أو أداة تجارية متخصصة مناسبة | معالجة حالات APFS وأنظمة معقدة حين لا تكفي الأدوات المفتوحة | تصدير صورة وتقرير للمستخدم أولًا؛ دمج آلي فقط إذا وجد API/CLI موثق وترخيص يسمح |
| Telemetry لجهاز قياس خارجي | تيار/فولت/واط مع توقيت يسمح بمقارنته بأحداث الفصل | يدعم موديلات ذات API موثق فقط؛ لا اختيار جهاز شراء قبل معرفة البروتوكول والحاجة |

[Sleuth Kit](https://www.sleuthkit.org/sleuthkit/desc.php) يعلن تحليل صور خام وصيغ أخرى وأنظمة بينها APFS. [libfsapfs](https://github.com/libyal/libfsapfs) يصنف نفسه تجريبيًا وتوجد ميزات APFS غير مدعومة. [fio](https://fio.readthedocs.io/en/latest/fio_doc.html) يوفر اختبارات أداء ومنع عمليات الكتابة عند استخدام readonly، لكن سياسة المنتج تؤجل الضغط على المصدر المريض. توثيق [OpenSuperClone](https://github.com/ISpillMyDrink/OpenSuperClone/wiki/Compatibility) يوضح أن NVMe يحتاج Generic Source Device Mode. [R-Studio](https://www.r-studio.com/data_recovery_macintosh/index.shtml) يعلن التعامل مع APFS وصور الأقراص؛ هذا خيار توسع لا شرط لاستخدام DRC.

[libewf](https://github.com/libyal/libewf/) يقدم أدوات قراءة وكتابة وتحقق لصيغ EWF؛ الفرع الحالي يصنف نفسه تجريبيًا ويشير إلى إصدارات مستقرة سابقة. اختيار إصدار مثبت واختبار تحويل الصور شرط قبل الدمج.

## 4. حدود أنظمة الملفات

| النظام/الحالة | المسار المبدئي | ما يجب ألا ندعيه |
| --- | --- | --- |
| NTFS، بما فيه أقراص ويندوز | صورة أو BlockSource، وقارئ TSK أو backend مختبر لعرض metadata والتصفح والاستخراج؛ لا يعتمد على تركيب macOS | أن استخراج البيانات يحفظ ADS/ACL أو الضغط أو كل metadata في أي وجهة دون اختبار وإظهار الفروق |
| exFAT وFAT12/16/32 | قارئ بنية يعرض الحقول والأدلة والجداول ويتيح استخراج الملفات؛ أدوات استعادة حسب القدرات المثبتة | أن دعم القراءة يعني دعم repair/format/undelete من كل backend |
| BitLocker | إتاحة تصوير خام؛ عرض نتيجة probe ومعلومات الحاوية التي يتيحها backend، وفك قفل بمفتاح المستخدم فقط عند وجود دعم مختبر | أن تصوير القطاعات المشفرة يفك التشفير، أو أن عدم قدرة المضيف على التركيب تمنع النسخ الخام |
| ReFS | واجهة backend مستقلة؛ تصوير خام متاح، وعمليات الملفات تحدد وفق قارئ مختبر | أن دعم NTFS يثبت دعم ReFS؛ لا إعلان تصفح أو استعادة غير مختبرين |
| Dynamic Disks / Storage Spaces أو وسيط متعدد الأجهزة | طبقة layout/container مستقلة، مع عرض معلومات المصدر وقراءة القطاعات المتاحة | أن تصوير عضو منفرد يعيد الحجم المنطقي كاملًا، أو أن الحاوية نظام ملفات بحد ذاتها |
| APFS سليم ويمكن فتحه | صورة مربوطة قراءة فقط على macOS ثم استخراج منطقي | أن جميع metadata قابلة للنقل لأي نظام وجهة |
| APFS تالف أو أقسامه مفقودة | صورة، اكتشاف أقسام، تحليل Sleuth Kit مختبر، وخيارات إضافية | أن TestDisk يعيد جميع ملفات APFS وأسماءها لأنه يستطيع اكتشاف قسم APFS |
| APFS مشفر | تصوير البيانات كما يقدمها الجهاز ثم فك القفل بمفتاح معروف في بيئة مناسبة | أن النسخ الخام أو carving يفك التشفير |
| HFS+/ext وغيرها | مسار تحليل حسب support matrix المثبتة الإصدار | دعم كامل لكل ميزة أو إصلاح عبر أداة غير مخصصة للنظام |
| نظام غير معروف أو metadata مفقودة | الصورة ثم carving ومعاينة التواقيع | أسماء أصلية وشجرة ملفات أو ملفات كاملة دائمًا |
| SSD بعد TRIM أو erase | حفظ ما يمكن قراءته وتحديد حدود النتائج | أن غياب البيانات قابل للعكس بواسطة فحص أعمق مضمون |

تفرق وثيقة [TestDisk](https://www.cgsecurity.org/wiki/TestDisk) بين اكتشاف أنظمة الأقسام وقائمة أنظمة undelete/copy. وتوضح وثيقة [PhotoRec](https://www.cgsecurity.org/testdisk_doc/photorec.html) فقدان الأسماء والبنية في carving.

هذه مصفوفة خطة وتحقق، وليست ادعاء دعم منفذ حاليًا. [Microsoft](https://learn.microsoft.com/en-us/windows/security/operating-system-security/data-protection/bitlocker/index) توثق BitLocker كتشفير؛ يعامل التشفير بصورة مستقلة عن نظام الملفات. لكل قارئ أعمدة منفصلة: التعرف، وmetadata، والتصفح، والاستخراج، واستعادة المحذوف، والتحقق، والإصلاح، والتهيئة، مع نظام المضيف والإصدار والقيود. لا عبارة «يدعم نظام الملفات» بدون تحديد العمليات.

## 5. مصفوفة الأنظمة

العناوين هنا تشير إلى **نظام تشغيل DRC**. «Windows لاحقًا» لا تؤجل دعم أقراص ويندوز وNTFS/exFAT/FAT داخل إصدار الماك.

| القدرة | مضيف macOS أولًا | مضيف Linux لاحقًا | مضيف Windows لاحقًا |
| --- | --- | --- | --- |
| اكتشاف وربط الأقسام بالأجهزة | Disk Arbitration + IOKit + diskutil | udev + sysfs + lsblk/blkid | Storage APIs + SetupAPI + DeviceIoControl |
| SMART | smartctl، حسب المسار الفعلي | smartctl، وتمرير SATA/NVMe بحسب الجسر | smartctl/APIs، بحسب الدعم |
| بيانات NVMe متقدمة | المتاح من OS/SMART، لا نفترض admin passthrough عامًا | nvme-cli، خاصة مع PCIe مباشر | APIs وتمرير موثق حسب الجهاز والنظام |
| إنقاذ خام | GNU ddrescue مثبت الاختبارات | GNU ddrescue، وخيارات لاحقة | backend معتمد بعد إثباته؛ Cygwin تجريبي ولا مساواة تلقائية |
| تحليل صور واستعادة | NTFS/exFAT/FAT أولويات ضمن TSK/PhotoRec/TestDisk؛ أنظمة أخرى وفق القدرة | قارئات مستقلة عن المضيف، بحسب البناء | قارئات مستقلة عن المضيف، بحسب البناء |
| منع تركيب للمصدر | Disk Arbitration والخدمة المناسبة | سياسات نظام/udev وتركيب RO مختبرة | سياسات نظام وتثبيت وصول/تركيب مناسبة مختبرة |
| تهيئة/أقسام | diskutil/gpt ومحرك نطاقات محدود | أدوات نظام ومكتبات مختبرة | Storage APIs وعمليات محدودة |
| حماية أعلى من الكتابة | حاجب مادي متوافق مع البروتوكول | حاجب مادي متوافق | حاجب مادي متوافق |
| قياس استهلاك فعلي | جهاز قياس إضافي | جهاز قياس إضافي | جهاز قياس إضافي |

هذه اختيارات backend، وليست نتائج اختبار أجهزة. [GNU ddrescue](https://www.gnu.org/software/ddrescue/manual/ddrescue_manual.html) يوصي بنظام POSIX ويذكر مشاكل تفسير أخطاء Cygwin. دعم Windows acquisition بوابة مستقلة، ولا نعيد كتابة rescue engine جديدًا دون دليل تفوق واختبارات مناسبة.

توثق Microsoft استخدام DeviceIoControl للاستعلام عن NVMe وتمرير أوامر محددة في [Working with NVMe Drives](https://learn.microsoft.com/en-us/windows/win32/fileio/working-with-nvme-devices). لا نعرض passthrough اعتباطيًا؛ تبقى الأوامر والقدرات مشروطة بالنظام والجهاز وسياسة السلامة.

## 6. ما يستبعد من البداية

- لا نستخدم dd كأداة الإنقاذ الرئيسية لمصدر بأخطاء؛ إدارة المناطق والاستكمال تحتاج محركًا مناسبًا.
- لا benchmark أو surface scan أو self-test طويلًا عند مجرد توصيل SSD غير مستقر.
- لا badblocks باختبار كتابة، ولا TRIM/discard، ولا sanitize، ولا firmware update في مسار إنقاذ البيانات.
- لا تشغيل daemon عام مثل smartd للمصدر المريض؛ نجمع ما نحتاجه عند الطلب وبحدود.
- لا تثبيت kernel extension قديم أو تقليل أمن الإقلاع تلقائيًا للحصول على SMART.
- لا تجريب bridge flags غير متحققة لمجرد أن USB VID/PID قريب من جهاز آخر.
- لا scraping لواجهة أداة تجارية أو الادعاء أن لها CLI دون مصدر موثق.
- لا افتراض أن المنفذ Type-C يعني مسار NVMe مباشرًا، أو أن القدرة المعلنة تعني السحب الفعلي.

## 7. قبول كل adapter قبل استخدامه

1. توثيق النظام والإصدار والقدرات والامتيازات والآثار الجانبية.
2. مخرجات JSON/Plist إن توفرت؛ وإلا parser مثبت الإصدارات مع fixtures وفشل صريح عند عدم الفهم. تحتفظ الحمولة الخام كاملة، وتعرض unknown/vendor fields والسجلات دون إسقاط أو اختزال.
3. قالب معاملات ثابت، والتحقق من الهدف والنطاق؛ منع تمرير shell نصي من الواجهة.
4. سياسة إيقاف وحفظ تقدم ومهل معروفة وحدود retries.
5. اختبارات source/destination/identity وفرض الحماية في المحرك والخدمة.
6. تثبيت مصدر binary وإصداره والتحقق منه ومراجعة إعادة التوزيع.
7. عدم إعلان النجاح قبل فحص خريطة النتائج وحالة الأداة كاملة؛ smartctl يعيد bitmask يجب تفسيره.
8. إبقاء حالة المصدر الأصلي وأعلامه منفصلة عن أي قيمة محسوبة؛ لا استنتاج سبب أو حكم صحة أو اقتراح إجراء من adapter.
